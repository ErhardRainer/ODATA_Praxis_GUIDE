SAP › Preguntas Frecuentes (FAQ)

¿Cuál es la diferencia entre OData v2 y v4 en SAP?

OData v2 es el estándar para la mayoría de las implementaciones de SAP Gateway. v4 es el estándar más nuevo y eficiente utilizado en los sistemas S/4HANA modernos. v4 ofrece un mejor rendimiento, metadatos simplificados y capacidades de consulta más potentes.

¿Por qué recibo errores de 'Property cannot be filtered'?

Esto ocurre cuando un campo está marcado con sap:filterable="false" en el $metadata. SAP suele restringir el filtrado en campos calculados o campos de texto largos para garantizar el rendimiento de la base de datos.

¿Cómo gestiono la autenticación para las llamadas OData?

SAP admite Basic Auth, OAuth 2.0 (recomendado) y SAML. Para las aplicaciones basadas en navegador, se suele utilizar la propagación de identidades (Principal Propagation). Utilice siempre HTTPS para proteger las credenciales.

¿Cuál es el número máximo de registros que puedo recuperar?

Los sistemas SAP suelen tener límites en el lado del servidor (p. ej., 1000 registros). Si necesita más, debe utilizar la **paginación** (siguiendo el enlace __next o utilizando $skip/$top).

¿Cómo llamo a funciones o acciones de OData?

Las funciones (GET) y las acciones (POST) son operaciones personalizadas definidas en el $metadata. Se llaman añadiendo el nombre a la URL del servicio, p. ej., .../GetQuickStats() o .../ReleaseOrder.

¿Puedo actualizar varios registros en una sola solicitud?

Sí, utilizando **solicitudes por lotes OData** ($batch). Puede agrupar varias operaciones GET, POST, PATCH o DELETE en un solo HTTP POST. SAP admite el procesamiento atómico (todo o nada) y no atómico utilizando tipos de contenido multipart/mixed.

¿Cómo gestiono los deep inserts (creación de entidades relacionadas)?

Los deep inserts permiten crear una entidad principal y entidades secundarias (como un pedido de ventas y sus posiciones) en una única solicitud POST anidando los datos secundarios dentro de la estructura JSON de la entidad principal.

¿Qué significa el error del token CSRF?

SAP requiere un token CSRF para todas las solicitudes de cambio de estado (POST/PUT/DELETE). Primero debe obtener un token a través de una solicitud GET con el encabezado x-csrf-token: fetch, y luego enviar el token recibido de vuelta en su solicitud de escritura posterior.

Conceptos Heredados

¿EntitySet frente a EntityType?

EntityType es la "Clase" (Plano), EntitySet es la "Tabla" (Colección de instancias).

¿JSON frente a XML?

Prefiera siempre JSON. Es más ligero, más rápido de analizar y utiliza menos ancho de banda.
