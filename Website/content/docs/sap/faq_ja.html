SAP › よくある質問 (FAQ)

SAP における OData v2 と v4 の違いは何ですか？

OData v2 は、ほとんどの SAP Gateway 実装における標準です。v4 は、最新の S/4HANA システムで使用される、より新しく効率的な標準です。v4 は、パフォーマンスの向上、メタデータの簡素化、およびより強力なクエリ機能を提供します。

「Property cannot be filtered」というエラーが出るのはなぜですか？

これは、$metadata 内でフィールドに sap:filterable="false" が設定されている場合に発生します。SAP はデータベースのパフォーマンスを確保するために、計算フィールドや長いテキストフィールドのフィルタリングを制限することがよくあります。

OData 呼び出しの認証はどのように処理すればよいですか？

SAP は Basic 認証、OAuth 2.0 (推奨)、および SAML をサポートしています。ブラウザベースのアプリでは、Principal Propagation (本人伝達) がよく使用されます。認証情報を保護するために、常に HTTPS を使用してください。

取得できるレコードの最大件数は？

SAP システムにはサーバーサイドの制限（例：1000件）があることがよくあります。それ以上のデータが必要な場合は、**ページング**を使用する必要があります（__next リンクをたどるか、$skip/$top を使用します）。

OData の関数 (Function) やアクション (Action) を呼び出すには？

関数 (GET) とアクション (POST) は、$metadata で定義されるカスタム操作です。サービス URL の末尾に名前を追加して呼び出します。例: .../GetQuickStats() や .../ReleaseOrder。

1 回のリクエストで複数のレコードを更新できますか？

はい、**OData バッチリクエスト** ($batch) を使用します。複数の GET、POST、PATCH、または DELETE 操作を 1 つの HTTP POST にまとめることができます。SAP は、multipart/mixed コンテンツタイプを使用して、アトミック（すべて成功かすべて失敗か）と非アトミックの両方の処理をサポートしています。

ディープインサート（関連エンティティの一括作成）はどのように行いますか？

ディープインサートを使用すると、親 JSON 構造の中に子データをネストさせることで、1 回の POST リクエストで親エンティティと子エンティティ（販売伝票とその明細など）を同時に作成できます。

CSRF トークンエラーの意味は何ですか？

SAP は、状態を変更するすべてのリクエスト (POST/PUT/DELETE) に対して CSRF トークンを要求します。まず x-csrf-token: fetch ヘッダーを付けて GET リクエストを送信してトークンを取得し、その後に送信する書き込みリクエストで受け取ったトークンを返送する必要があります。

レガシーコンセプト

EntitySet と EntityType の違いは？

EntityType は「クラス」（設計図）、EntitySet は「テーブル」（インスタンスの集合）です。

JSON と XML どちらを使うべき？

常に JSON を優先してください。より軽量で解析が速く、帯域幅の消費も少なくなります。
